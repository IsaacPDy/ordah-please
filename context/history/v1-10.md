# V1-10 Web/PWA reference UI redesign

## Implemented

The supplied phone references define the existing web/PWA visual direction. Home uses Session-First; the corresponding Groups, Favorites, History, and session-detail references apply to their routes. Unpictured screens inherit the shared palette, typography, controls, borders, and cards. Android is unchanged.

- Added the white phone canvas, green actions, native system typography, compact shell, root navigation, and responsive centered layout.
- Home displays authorized active sessions, personal usuals, recent orders, and existing catalog discovery. Sessions has functional Active/Past tabs; History retains progressive loading and authorized lazy order logs with group filtering and month headings.
- Groups expose Overview, History, and Members while preserving owner-only rename/invite actions and eligible manager order setup. Favorites has functional restaurant filters and retains removal.
- Order setup uses three interactive screens with the reference's four milestone labels and inline Review on the final screen. Inspection found no separate existing fourth screen. Selection, validation, delivery fields, voting configuration, and submission payload remain intact; step changes focus the heading.
- Order details display progress and photo cards when real menu-version assets exist. Terminal orders retain authorized saved food lines, participant disclosure, totals, and Details selection. Summary photos use a compact existing-query projection; no migration or new provider was needed.

## Limits and remaining acceptance

This is a screenshot-derived implementation using real application data, not a pixel-identical copy of sample identities or assets. Missing group covers/member photos use existing initials or icons, and older saved menu versions can lack food imagery. Exact imported long names wrap and retain their original wording. No operating-system status bar is fabricated. Existing unfinished restaurant-voting/handoff product stages remain unchanged.

Authorized admin pages and separate Owner/Manager/Member accounts were not exercised live in this pass. Styling reaches those routes through shared tokens and controls; this does not establish their full browser acceptance. Production deployment was not verified. A concurrent desktop stylesheet import briefly interrupted the final browser check. Once its file arrived, a reload confirmed the signed-in Home rendered again at localhost:3000. The server remains running. Git commit/merge/push are deferred while the separate “Add desktop browser sizing” chat continues modifying this same branch and shared files; its desktop changes are not part of the automated evidence reported here.
