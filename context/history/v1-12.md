# V1-12 Member reference layout fidelity

Implemented October 6, 2026. The user requested correcting History, Groups, Favorites and social-session screens against Image #1, then explicitly requested applying those layouts to mobile too.

## Changes

- Groups: white membership cards with real member previews/roles, an eligible Start group order link, and recent authorized history with real catalog thumbnails. Cards form two desktop columns and one mobile column. Independent group/history reads run together; optional history failure keeps group navigation usable.
- History: separate date badges, food thumbnails, compact monthly rows, counts of loaded orders, group/month filters, disclosure chevrons, and a subtotal column after authorized details load. Progressive pagination and participant/item authorization are preserved.
- Favorites: reference introduction, By restaurant/All favorites switch, visible branch headings and favorite counts, ranked food-photo cards, and accessible bookmark removal. Three desktop/two mobile columns retain imported names and prices.
- Social sessions: desktop navigation sidebar, group identity and restaurant/deadlines, response progress, compact manager participant disclosures and adjacent order summary. Mobile uses a horizontal navigation strip and stacks participants/summary. Own-user summaries filter food lines by user ID. Existing picker, settings actions, permission checks and terminal details remain.

## Limits

This matches reference composition with real account data, rather than the sample people, photographs, totals or group count. Group photos/member photo URLs are not available in these read models, so existing icons/initials remain. History subtotal reads stay lazy and month counts explicitly describe loaded rows. Suggested groups, reminders, member group creation and group-wide favorite ordering lack existing workflows and are omitted. Restaurant voting/handoff placeholder stages retain their prior behavior. Production deployment, separate-role browser acceptance, and a live food-confirmation session were not verified; food-confirmation behavior is covered by affected tests.
