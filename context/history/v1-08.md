# V1-08 Progressive web performance

## Implemented

- Home loads active orders separately from six shared restaurant previews, so one failing source no longer blanks both sections.
- Orders loads active work plus ten compact terminal summaries. Participant totals load only when a history card opens, and older summaries load by cursor page.
- Restaurant, group, membership, user, order-count, and admin catalog reads are bounded, batched, branch-scoped, concurrent, or deterministically ordered instead of loading the whole dataset or repeating one query per row.
- Shared published catalog reads use tagged hour-scale server caching. Successful catalog imports and edits invalidate the affected cache tags. Identity, permissions, favorites, groups, and orders remain outside the shared cache.
- Member and admin routes partially prerender a neutral shell, then stream authenticated content. The fallback never receives protected page children and respects reduced-motion preferences.
- Home links to a paginated restaurant index. Admin Groups shows a real grouped active-order count instead of a placeholder zero.
- Client history guards prevent rapid clicks from starting duplicate detail or next-page requests.

## Acceptance boundary

- The available signed-in account was both Platform Admin and Group Owner. Manager-only, Member-only, removed-member, retry, and later-page behavior is covered by unit and provider tests but was not repeated with separate live accounts.
- Timing values are browser-controller wall times from the same production browser, not laboratory Web Vitals. They prove the perceived blank wait was replaced by a fast stable shell; they do not claim every database-backed section finishes within the shell-arrival time.
