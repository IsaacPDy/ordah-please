- V1-06 mobile admin decision route, Home card, and identity-summary endpoint

## Session Notes

- V1-06 was implemented on `task/V1-06-platform-admin-approval` off the reviewed V1-05 `main`. The platform-admin approval boundary is now closed end-to-end: a group owner submits an admin-access request (already possible in V1-05), an existing platform-admin lists the pending queue and decides approve or reject with an optional reason, and the requester's `is_platform_admin` flag flips transactionally with one immutable audit row.
- New domain contracts add `parseDecideAdminAccessRequestRequest` and `parseListPendingAdminAccessRequestsResponse`, plus the `AdminAccessRequestSummary` shape and a new `NOT_FOUND` error code that the route layer maps to HTTP 404. The contracts package sources a fresh `AdminAccessRequestId` brand from `@ordah-please/domain`.
- New repositories in `packages/db` cover `findAdminAccessRequestById`, `decideAdminAccessRequest`, `listPendingAdminAccessRequests`, and `promoteToPlatformAdmin`. The decide path is transactional: it locks the request row, applies the role promotion on approval, writes the deciding audit, and idempotency-key dedupes repeated decisions. Audit events are `platform_admin.approved` and `platform_admin.rejected` with key `platform_admin:decide:<requestId>:<decision>`.
- The access service exposes `decideAdminAccessRequest(command, runner)` and `listPendingAdminAccessRequests(runner)` with their own typed `Repositories` interfaces and full RED→GREEN coverage. Both were validated end-to-end by the route-handler Vitest suite.
- Two new platform-admin-gated trusted API routes join the access surface: `POST /api/access/admin-requests/decide` and `GET /api/access/admin-requests/pending`. A third supporting route, `GET /api/identity/me`, returns the minimum identity summary the native Home card needs (`{ isPlatformAdmin, pendingAdminRequestCount }`) without an extra repository call for non-admins. The route layer enforces platform-admin via `isPlatformAdmin(identity)` and rejects non-admins with `PublicApiError("FORBIDDEN", ...)` mapped to HTTP 403.
- The web `/admin/access-requests` page replaces the prior stub with a server component that renders `AdminDecisionPanel` (client wrapper) over `AdminDecisionView` (pure presentational). The decide and pending routes already enforce the platform-admin role, so non-admins land on the panel's "Only platform admins can review access requests." state on a 403 — matching the existing `TeamAccessPanel` auth pattern. A layout-level server gate was intentionally skipped because the codebase has no server-side session-reading pattern yet and every other `/admin` page is still an honest EmptyPage stub.
- Mobile gains a new `/admin/access-requests` Expo Router route outside `(member)` (bypasses the tab bar), a React Native Paper `AdminDecisionPanel` that hits the pending and decide routes via the existing cookie-only `authenticated-request` helper (no bearer token — matches V1-05 Better Auth Expo pattern), and a conditional `HomeAdminCard` on the member Home screen that renders only when `identity.isPlatformAdmin` is true and deep-links into the new route. Non-admins see honest no-access states; admins see the empty-state card when no requests are pending. `ShellScreen` gained an optional header slot to mount the card above the empty-state surface.
- Provider-free verification reached 47 Vitest files with 239 tests and 9 mobile Jest suites with 29 tests. `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build`, and `git diff --check` all exit clean.
- T8 verification uncovered three pre-existing issues that earlier subtasks had missed because provider-free Vitest stays green even when root-level `tsc --noEmit`, `eslint .`, and `prettier --check` do not: a TS2532 in the contracts test under `noUncheckedIndexedAccess`, an eslint-disable directive for an unconfigured `react-hooks/exhaustive-deps` rule, and pre-existing Prettier drift across T2–T7 V1-06 files. All were fixed in a dedicated verification-cleanup commit before squash.
- Live acceptance was completed by the user across web and Android: the `/admin/access-requests` flow approved a pending request from a second owner account, the requester's `is_platform_admin` flag flipped in Neon, and exactly one audit row with action `platform_admin.approved` was written.
